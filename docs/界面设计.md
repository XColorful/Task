# 界面设计

> 本文档描述 Task 软件的 GUI 布局、交互模式及各界面状态的行为规范。

## 一、通用布局

### 1.1 三区布局

所有界面（主界面、Tasker 界面、设置界面）采用统一的三区布局：

```
┌──────────────────────────────────────┬──────────┐
│                                      │ 常驻区   │
│         内容显示区                    │ (右侧)   │
│    (主界面: Tasker 可点击列表)        │ 可用指令 │
│    (Tasker界面: Task 表格)            │ 点击执行 │
│                                      │ 快捷按钮 │
├──────────────────────────────────────┤ search   │
│         系统输出区 (实时 log)         │ 结果表格 │
├──────────────────────────────────────┤          │
│         输入框 (多行显示，不自动换行)  │          │
└──────────────────────────────────────┴──────────┘
```

- **输入框**（底部）：键盘输入实时反映在此。支持较长文本分行显示（窗口宽度不变时自动折行），但不自动插入换行符
- **系统输出区**（输入框上方）：等价于旧软件的命令行输出——系统提示、操作反馈、错误信息等实时 log
- **内容显示区**（上方主体）：根据当前界面类型显示对应内容
- **常驻区**（右侧）：三部分——可用指令（可点击）、快捷按钮（可点击）、search 结果（表格样式，直到退出 Tasker 或下次 search 时刷新）

### 1.2 窗口关闭行为

- 窗口右上角的 **× 按钮需去除**，防止用户习惯性点击关闭而退出软件
- 退出软件的唯一方式：右下角任务栏托盘右键菜单 → "退出"；或在主界面输入框输入 `exit`
- 关闭窗口的操作（如 Alt+F4 或任务栏关闭）等同于**最小化到托盘**（hide 行为）

### 1.3 自动保存触发时机

以下时机触发自动保存：
- 快捷键隐藏窗口 / 手动输入 `hide` 指令隐藏到托盘时
- 退出 Tasker 回到主界面时（如果在 Tasker 界面内）
- settings 界面 exit 回到主界面时

### 1.4 JSON 顺序保持

**所有 JSON 文件读写必须保持键和数组元素的插入顺序。** Python 3.7+ 的 dict 插入顺序保证。`taskers.json` 中 Tasker 的排列顺序即为主界面列表的显示顺序。segment JSON 文件中 Task 的顺序即为表格显示顺序。

### 1.5 常驻区的使用

常驻区从上到下分为三个区域：

**① 可用指令列表（Tasker 界面内）：**
- 显示当前 Tasker 支持的所有指令名（如 `new`、`search`、`delete`、`edit` 等）
- 每个指令为可点击的按钮/文本——点击即等效于在输入框输入该指令并回车
- 在主界面下可用指令为全局指令（`get`、`add`、`backup`、`settings` 等）

**② 快捷按钮：**
- 快捷按钮模板数据存储在 `taskers.json` 中，绑定在对应的 Tasker 属性上
- **主界面的快捷按钮列出所有 Tasker 的快捷按钮**——点击后自动进入对应 Tasker 并执行按钮动作
  - 实现方式：Tasker 类设计时即支持从外部触发快捷按钮（不限于 Tasker 界面内部的按钮点击），通过 Tasker 对象的方法直接调用，而非依赖 UI 信号
- 每个按钮包含：自定义指令名、显示标签、预设字段模板（日期、属性、内容、注释的默认值）
- 按钮可增加或删除，点击即用模板创建一条 Task
- 模板中可标记字段为"使用默认值"——如日期不填则自动取当天

**③ 搜索结果（Tasker 界面内，执行 search 后）：**
- 以**表格样式**渲染搜索结果（对齐列、标题行），同旧软件搜索的表格返回格式
- 结果常驻直到退出 Tasker 或下一次 search 时刷新

## 二、主界面

### 2.1 默认状态

**背景层（半透明）：**
- 软件名称
- 作者名
- GitHub 仓库链接
- 版本号

以半透明水印形式渲染在内容显示区的背景上。

**前景层（内容显示区主体）：**
- Tasker 可点击列表，按 `taskers.json` 中读取的顺序排列
- 每个 Tasker 显示为一行：标签名 + 类型标识
- 点击某个 Tasker → 进入该 Tasker 界面
- 也支持在输入框中输入 Tasker 名（或索引）回车进入（等价旧软件 `get` 行为）

**输入框支持的操作：**
- 直接输入 Tasker 名或索引 → 进入该 Tasker
- `/get Tasker名` → 进入该 Tasker
- `/add` → 弹出创建 Tasker 对话框
- `/edit Tasker名` → 编辑 Tasker
- `/delete Tasker名` → 删除 Tasker
- `/info Tasker名` → 查看 Tasker 详细信息
- `/sort 字段` → 排列 Tasker 列表
- `/settings` → 进入设置界面
- `exit` → 退出软件

**常驻区（主界面）：**
- 可用指令列表（全局指令）
- **所有 Tasker 的快捷按钮汇总展示**——每个按钮标注其所属 Tasker

### 2.2 设置界面（settings）

输入 `settings` 或 `/settings` 进入。

内容显示区切换为配置界面：每一项配置显示为一行文本标签 + 右侧输入控件。

配置项包括：
- `SHOW_TIPS`：是否显示提示信息（布尔值）
- `AUTO_SAVE`：是否自动保存（布尔值）
- `BACKUP_INTERVAL`：备份间隔天数（整数）
- `BACKUP_TOTAL`：最大备份数（整数）
- `DEFAULT_METHOD`：默认指令（字符串）
- 设置界面专属项：进入 Tasker 时显示的最近记录条数（整数）、HTTP 服务端口（整数，默认 19527）、每段最大记录数（整数，默认 500）

**验证规则**：当从设置界面 exit 回到主界面时，检查所有配置项的输入合法性。不合法的项保留修改前的值（不更新）。

**保存**：从设置界面 exit 时自动保存所有配置。

### 2.3 backup 指令

- 创建以当前时间戳命名的文件夹（如 `backup_2026_07_11 - 14-30-00/`）
- **不是直接复制文件**：遍历所有 Tasker，逐个执行全量读取 → 将读到的完整数据写入备份文件夹。确保备份内容为当前内存状态的一致性快照

**reload 指令：**
- 用户选择备份文件夹
- 首先检查该文件夹下是否存在 `taskers.json`——存在才视为有效备份
- 遍历备份文件夹，读取全部 Tasker 数据到临时内存结构与当前数据对比
- **在整个备份读取完成之前不进行任何替换或写入**
- 读取完成后，用户确认 → 一次性替换当前存储目录的文件并重建内存状态

## 三、Tasker 界面

### 3.1 taskers.json 索引文件

存储在配置的根目录下，内容（键和数组均保持插入顺序）：

```json
{
  "taskers": [
    {
      "id": "a1b2c3d4",
      "type": "default",
      "label": "班级",
      "description": "班级事务记录",
      "folder": "班级_a1b2c3d4",
      "quick_buttons": [
        {
          "command": "hw",
          "label": "记作业",
          "preset": {"attribute": "作业", "content": "", "use_default_date": true}
        }
      ]
    },
    {
      "id": "e5f6g7h8",
      "type": "timer",
      "label": "计时器",
      "description": "",
      "folder": "计时器_e5f6g7h8",
      "quick_buttons": []
    }
  ]
}
```

**设计要点：**
- 不保存 Task 数量（否则每次增删都会触发 OneDrive 同步 taskers.json）
- `quick_buttons` 绑定在 Tasker 上：自定义 command 名、显示 label、预设字段模板
  - `use_default_date: true` → 日期不填则取当天
  - 预设中 `content` 为空字符串 → 点击后仍需用户输入内容
- **Tasker 类设计时需支持从外部触发快捷按钮**（主界面点击按钮 → 传入 Tasker 对象 + 按钮模板 → 直接调用创建流程），不依赖 UI 信号
- 文件夹名包含唯一 id，避免重名
- Tasker 界面内操作时，只能操作该 Tasker 文件夹内的文件
- taskers.json 的修改频率极低（创建/删除/重命名 Tasker、编辑快捷按钮时）

### 3.2 快捷按钮模板的使用逻辑

点击快捷按钮时：
1. 如果在主界面点击 → 先自动进入对应 Tasker，再执行第 2 步
2. 读取按钮的 `preset` 模板
3. `use_default_date == true` → `date = YYYY_MM_DD()`（当前日期）
4. `use_default_date == false` 且 `preset.date` 有值 → 使用模板中的固定日期
5. `attribute` / `content` / `comment` 同理——标记为使用默认值则取当前上下文默认值，否则取模板固定值
6. 如果 `content` 为空（模板未填且无默认值），弹出输入框让用户补充后再创建
7. 创建成功后 `usage_count++`，按钮按使用频率排序

### 3.3 内容显示区（默认 Tasker）

**进入时的初始加载：**
- 读取最近的两个 segment JSON 文件到内存（按文件名排序取最后两个）
- 显示最近若干条记录（条数由 settings 中配置决定）
- 内容显示区顶部带表格标题栏（字段名：索引、日期、属性、内容、注释）
- 支持鼠标滚轮翻页，动态加载更多 segment 文件

**delete 模式：**
- 输入 `delete` 进入删除状态：内容显示区中每条 Task 右侧出现 × 按钮
- 点击 × 按钮删除该 Task → 从列表移除 → 自动退出 delete 模式
- 也可通过输入索引/搜索词来定位并删除（同旧软件行为）

**edit 模式（多候选项时）：**
- 输入 `edit 搜索词` 并且有多个候选项时，内容显示区切换为候选表格（同旧软件的表格+索引格式）
- 用户输入索引选择要编辑的 Task → 进入编辑状态

**search 结果：**
- 搜索结果渲染到右侧常驻区，以**表格样式**（对齐列、标题行）展示
- 直到退出 Tasker 或下一次 search 时刷新

### 3.4 默认 Tasker 的分段读写策略

**Segment 文件组织：**
Tasker 文件夹下不设 index.json。直接按文件名排序确定 segment 顺序：

```
{tasker_folder}/
├── segment_0001.json    # 第 1-500 条
├── segment_0002.json    # 第 501-1000 条
├── segment_0003.json    # 第 1001-1500 条
└── ...
```

默认每个 segment 存 **500 条 Task**（可在 settings 中配置）。新增记录追加到编号最大的 segment；该 segment 满 500 条时创建下一个 segment。

**初始加载（只读最近两段）：**
进入 Tasker 时，按文件名排序取最后两个 segment 加载到内存。

**索引使用规则：**
- **负数索引（倒序）**：如 `-1` 表示最后一条。如果涉及的记录在已加载的两个 segment 范围内 → 直接使用内存数据。如果超出范围 → 需要加载更早的 segment
- **正数索引（正序）**：如 `0` 表示第一条。使用正数索引会**触发全量加载**——读取所有 segment JSON 到内存并拼接为完整列表

**脏数据追踪与写入策略：**
Tasker 对象内部维护两个集合：
- `loaded_segments: set[str]`——本次会话中从磁盘读取过的 segment 文件名
- `dirty_segments: set[str]`——本次会话中被修改（增/删/改）过的 segment 文件名

写入时的判定逻辑：
1. 只有 `loaded_segments` 中的文件在退出时参与写入（未加载过的 segment 原样保留在磁盘，不读不写——非脏不写）
2. `dirty_segments` 中的文件必须写回磁盘
3. 扩容边缘：最新 segment 满 500 条 → 写入时创建新 segment（`segment_{N+1}.json`），旧 segment 保持不变
4. 缩容边缘：某 segment 的记录全部被删除 → 写入时跳过该文件（等同于从磁盘删除）。如果缩容后总数不足一个 segment，允许只有一个 segment
5. 全量加载后的中间修改：如果修改了一条记录导致其序号变化（如在中间插入/删除），可能影响之后所有 segment 的编号边界。这种情况下标记所有受影响 segment 为脏
6. 原子写入：任何时候写 segment 都先写 `segment_XXXX.json.tmp` 再 rename

扩容和缩容恰好卡在 500 边界时——以**写入前瞬间的状态**为准判定。例如最新 segment 当前 499 条 → 新增 1 条变为 500 → 写入时检查 500 = 阈值 → 不创建新 segment（未超过），当前 segment 标记为脏并写入。

**退出 Tasker 时：**
- 执行保存（按脏数据追踪策略写入）
- 释放全部内存中加载的 segment 数据

### 3.5 新建 Task 的交互

输入 `new` 进入新建状态：
- 内容显示区顶部出现一行空的 Task 表单
- 用户在输入框中输入内容 → 同步更新到内容显示区中的 Task 表单项
- 每输入完一个字段按回车进入下一个字段
- 输入过程中随时可以 `exit` 取消
- 所有字段填写完毕 → 确认创建 → 追加到 task_list → 标记 dirty → 触发保存检查

### 3.6 输入预处理链

输入在传给指令解析器之前，按顺序经过预处理步骤。当前预处理链：

```
原始输入
  → 预处理步骤 1: '+' 前缀替换
     如果输入以 '+' 开头 → 替换为 "search " + 原始输入[1:]
  → 预处理步骤 2: (预留扩展)
  → 预处理步骤 3: (预留扩展)
  → 交给指令解析器
```

预处理链设计为**可插拔的步骤列表**，后续添加新的预处理（如自定义别名替换）只需追加步骤，无需修改核心解析逻辑。每个预处理步骤是一个函数，接收原始字符串，返回处理后的字符串（或原样返回）。

`/` 前缀：
- `/指令` → 强制识别为指令（同旧软件），在解析器中处理，不属于预处理链

直接输入数字：
- 视为索引搜索

### 3.7 其他 Tasker 类型

**Timer / Account / Label Tasker**：当前阶段内容显示区暂时保持与旧软件相同的文本输出格式。后续为每种 Tasker 类型设计专用视图时再更新此文档。

**Wallet 格式（使用 default Tasker 记录）：** wallet 是用户在 default Tasker 中用 content 字段约定的记账格式（如 `"; "` 分隔各项收支）。目前 default Tasker 能正常读取数据显示，但 content 内部的特殊解析（从 default 转换成待添加的 wallet 类型）待后续完成。Account 仍复刻旧软件的独立实现。

## 四、图表分析（外部浏览器 + HTTP 服务）

### 4.1 基本流程

1. 用户点击"打开图表"→ 选择图表类型
2. 软件启动本地 HTTP 服务（`127.0.0.1:{端口}`）
3. 处理完图表需要的初始数据后，`webbrowser.open()` 打开系统默认浏览器
4. HTML 页面加载 ECharts / ECharts GL（CDN），渲染初始图表

### 4.2 图表模式下的输入框行为

图表打开后，输入框**不受影响**——用户可继续正常进行 CRUD 操作。HTTP 服务在后台持续运行以响应后续请求。

### 4.3 动态数据图的并发安全

对于**未来待添加的 3D 图表**（如按月翻页时动态读取数据）：
- 浏览器 JS 通过 `fetch()` 向本地 HTTP API 请求新数据
- HTTP 服务在请求处理中读取存储层数据（**只读**——分析引擎不写入）
- 主进程同时在写入存储层时通过原子写入（tmp → rename）保证文件完整性
- 无需加锁——存储层的原子写入策略天然保证了并发安全

### 4.4 返回

- 点击主窗口"返回"按钮或在输入框输入 `exit` → 停止 HTTP 服务 → 释放端口
- 浏览器标签页由用户自行关闭

## 五、项目目录

新代码全部放在根目录 `src/` 下，旧软件代码保持在根目录不动，二者互不混用：

```
Task/
├── main.py               # 旧软件入口（保留不动）
├── package/               # 旧软件模块（保留不动）
├── src/                   # 新软件代码
│   ├── main.py            # 新软件入口
│   ├── core/              # 核心抽象 + 存储层
│   ├── extensions/        # 扩展模块
│   ├── ui/                # GUI 层
│   ├── analysis/          # 分析引擎
│   ├── visualization/     # 3D 数据构建
│   ├── io/                # 导入导出
│   ├── config/            # 配置管理
│   └── util/              # 工具类
├── docs/                  # 文档
└── data/                  # 默认数据目录
```

旧软件的 pkl 文件也在根目录，新软件迁移时可直接通过相对路径读取。
