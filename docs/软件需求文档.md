# Task 软件需求文档

> 版本 2.0 — 基于旧项目重构的新版本需求规格

## 一、项目背景

### 1.1 旧项目概述

Task 项目始于约 2023 年 9 月（高中阶段），是一个基于 Python 命令行的个人日常记录工具。项目采用"容器-记录"的层级数据模型，通过插件式模块（Package）扩展功能。经过约两年的持续开发和使用，积累了日常事务记录（班级事务、作业、通知、缴费等）、计时器记录、账号管理等多类数据。

旧项目的架构特点和历史背景详见 `架构.md`，各模块功能详见 `功能说明.md`，数据格式详见 `txt保存格式.md`。

### 1.2 重构动机

旧项目作为编程早期作品，存在以下限制：

1. **纯命令行交互**：无图形界面，日常使用时需切换到终端并记忆指令，操作效率受限
2. **pkl 存储不可读且不友好同步**：Python pickle 格式不支持文本查看和手动编辑，单个大文件在 OneDrive 上任何修改都会触发全量同步
3. **架构耦合**：模块间通过全局列表注入实现隐式依赖，`default_pkg` 与 `account`、`timer` 等扩展的功能关系不清晰，新增功能需要理解并修改多处代码
4. **无图表可视化**：虽有 matplotlib 统计功能，但为弹出式独立窗口，无法融入日常使用流程
5. **模板继承链过长**：部分类继承三层才能到达具体实现，不利于快速定位和修改

随着开发者技术成长，有必要用成熟的工程能力重新设计并实现项目。

## 二、运行环境

### 2.1 操作系统
- **主环境**：Windows 11 (x64)
- 理论上软件可在 macOS/Linux 运行，但打包和全局热键功能仅针对 Windows 验证

### 2.2 软件依赖
- Python 3.12+（开发环境，打包后无需用户安装）
- 所有依赖通过 `pip install -r requirements.txt` 安装

### 2.3 硬件要求
- 内存：建议 4GB 以上（软件实际占用 < 200MB）
- 存储：软件本体 < 100MB，数据文件依记录量而定（典型 < 5MB）

### 2.4 外部服务
- OneDrive（可选）：用于多设备数据同步，软件本身不内置云同步
- 系统默认浏览器：用于图表和 3D 可视化（软件通过 `webbrowser.open()` 打开）

## 三、功能需求

### 3.1 核心 CRUD 功能（继承旧项目并优化）

#### 3.1.1 日常记录

每一项记录包含四个字段：**日期**（`YYYY_MM_DD`，默认当天）、**属性**（分类标签）、**内容**（自由文本）、**注释**（可选）。

- 创建记录：GUI 表单对话框 或 内联输入框直接输入内容后回车
- 编辑记录：点击记录 → 弹出编辑面板 → 修改各字段（回车保留原值）
- 删除记录：选中 → 右键删除或按 Delete 键 → 确认
- 搜索与筛选：搜索栏实时过滤当前 Tasker 的所有记录
- 记录容器（Tasker）管理：左侧列表展示所有 Tasker → 右键创建/删除/重命名/排序

内容字段保持旧项目约定格式——用 `"; "`（分号+空格）分隔多项信息，支持 `file:`/`jpg:`/`pdf:`/`键:值` 等引用格式。

#### 3.1.2 计时器

- 创建计时记录：开始时间（默认当前时间）+ 结束时间（可留空）+ 属性 + 内容 + 注释
- 快速开始计时：点击预设快捷按钮即可开始一个新计时
- 结束进行中的计时：点击"结束"按钮，自动填入当前时间
- 进行中计时提示：状态栏或托盘区显示当前进行中的计时
- 搜索计时记录：按时间范围、属性、内容等多维度筛选
- 时长自动计算：基于 start_time 和 end_time 计算持续时长，格式化为 `Xd Yh Zm`

#### 3.1.3 账号管理

- 创建账号记录：账号类型（平台名）、标签（搜索用）、密码
- 密码查询与复制：搜索账号 → 自动复制密码到剪贴板 → 提示"已复制"
- 补充信息：支持 description、login_name、verified_phone、verified_email、linked_account 等可扩展字段
- 密码更新：更新密码时旧密码自动迁移到历史记录
- 关联账号：记录关联的其他账号（如"Google → GitHub"），搜索时联动查找

#### 3.1.4 数据管理

- 导出人类可读格式：按日期/按Tasker/按创建日期排序输出纯文本文件
- 导入旧数据：一次性迁移脚本，读取旧项目 pkl 和 txt 备份，转换为新格式
- 手动编辑后导入：支持将手动修改后的可读 txt 文件重新导入
- 数据备份：创建时间戳命名的文件夹，遍历所有 Tasker 逐个全量读取并写入备份文件夹（不直接复制文件，确保内存状态一致性快照）

### 3.2 新增功能

#### 3.2.1 GUI 图形界面

- **统一三区布局**：所有界面共用以下布局（详见 `界面设计.md`）
  - **顶部内容显示区**：主界面显示 Tasker 可点击列表（背景半透明显示 GitHub/作者/版本号）；Tasker 界面显示 Task 表格；设置界面显示配置项
  - **中部系统输出区**：实时 log——操作反馈、错误提示、状态信息
  - **底部多行输入框**：键盘输入实时反映，长文本自动折行但不插入换行符。输入先经过**预处理链**（`+` → `"search "` 替换，预留扩展槽位）再解析
  - **右侧常驻区**：可用指令列表（可点击执行）、快捷按钮（主界面列出所有 Tasker 的按钮，点击自动进入对应 Tasker 并执行）、search 结果（表格样式）
- **窗口关闭行为**：× 按钮已去除，关闭窗口等同于最小化到托盘。退出软件仅通过托盘右键菜单或主界面输入 `exit`
- **主界面**：半透明背景显示 GitHub/作者/版本号，前景为 Tasker 可点击列表（按 `taskers.json` 顺序排列）
- **Tasker 界面表格视图**：Task 以表格展示（列：索引、日期、属性、内容、注释），顶部带标题栏，支持鼠标滚轮。进入时两段懒加载——只加载最近两个 segment
- **delete 模式**：每条 Task 右侧出现 × 按钮，点击即删除并退出 delete 模式
- **edit 多候选**：内容显示区切换为候选表格，用户输入索引选择
- **系统托盘常驻**：最小化到托盘，全局热键（如 `Ctrl+Shift+T`）唤出
- **自动保存时机**：隐藏到托盘时、退出 Tasker 时、退出设置界面时

#### 3.2.2 内联输入（键盘交互）

底部多行输入框是软件的主要交互入口，等效于旧项目的命令行。

- 直接输入 Tasker 名或索引 → 进入该 Tasker（也支持点击内容显示区中的 Tasker 列表进入）
- `/get 班级` → 进入 Tasker；`/add` → 创建 Tasker；`/settings` → 设置界面
- `+搜索词` → 进入预处理链：`startswith("+")` → 替换为 `"search 搜索词"` → 交给解析器。预处理链可扩展（预留槽位用于未来别名替换等）
- 在 Tasker 内输入 `new` → 内容显示区出现空 Task 表单，输入框逐字段填写
- `exit` → 回退（Tasker 内回到主界面，主界面内退出软件）

#### 3.2.3 图表分析（2D）

图表分析通过**外部浏览器**展示，软件启动本地 HTTP 服务提供数据 API。

- **打开图表**：点击工具栏"图表"按钮 → 选择图表类型 → 软件启动本地 HTTP 服务（`127.0.0.1`，端口可配置）→ 自动在系统默认浏览器中打开图表页面
- **图表模式**：图表打开后输入框不受影响——用户可继续正常 CRUD 操作。返回通过输入 `exit` 或点击返回按钮
- **数据增量加载**：浏览器中的 JS 通过 `fetch()` 向本地 HTTP API 请求数据。用户翻月份/切换筛选条件时增量加载，多年数据不会一次性传输
- **图表类型**：
  - 属性分类统计：饼图 + 柱状图
  - 月度趋势分析：折线图 + 柱状图
  - 时长分析：按属性/按月的柱状图
  - 热力图：日期 × 属性矩阵
- **返回**：点击"返回"按钮 → 停止 HTTP 服务 → 释放端口 → 恢复主界面。浏览器标签页由用户自行关闭

#### 3.2.4 3D 可视化

- **月度网格柱状图**：在浏览器中通过 ECharts GL bar3D 渲染
  - 以 **7 列为一行**（每周 7 天）的网格布局，按**月份分隔**
  - 每根柱子高度 = 该 Timer 记录的持续时长
  - 颜色 = 属性分类
- **跨月逻辑**：当前月数据排完后强制换行，新月份从新行开始
- **交互**：在浏览器中鼠标旋转/缩放/平移视角，悬停柱子显示记录详情
- **月份切换**：翻页查看不同月的数据——每次翻页触发 `fetch()` 请求增量数据。HTTP 服务为只读查询，存储层的原子写入（tmp → rename）天然保证并发安全——不会读到半写文件
- **资源管理**：关闭标签页即释放 GPU 资源；停止 HTTP 服务即释放端口

### 3.3 存储方案

#### 3.3.1 JSON 分段存储

每个 Tasker 对应一个文件夹，内部以 segment 文件分段存储：

```
{数据目录}/
├── taskers.json                   # 所有 Tasker 的简要索引（不存 Task 数量）
├── {tasker_folder_1}/
│   ├── segment_0001.json         # 第 1-500 条
│   ├── segment_0002.json         # 第 501-1000 条
│   └── ...
└── {tasker_folder_2}/
    ├── segment_0001.json
    └── ...
```

**按数量分段：** 默认每段 500 条 Task（可在 settings 中配置）。不设 index.json——按文件名排序直接确定 segment 顺序和最新两段。新增记录追加到编号最大的段，该段满 500 条时创建新 segment。

**索引文件 (`taskers.json`)：** 不存储各 Tasker 的 Task 数量——避免每次增删记录都触发 OneDrive 同步此文件。仅存储 id、type、label、description、folder、quick_buttons 模板。该文件仅在创建/删除/重命名 Tasker、编辑快捷按钮时写入。Tasker 排列顺序即为主界面列表显示顺序（JSON 顺序保持）。

**启动优化：** 启动时只读 `taskers.json`（所有 Tasker 的简要信息），不加载具体 segment。进入 Tasker 后才按需加载。

**两段懒加载：** 进入 Tasker 时按文件名排序取最后两个 segment 加载到内存。

**正数索引触发全量加载：** 使用正数索引（如 `0` 表示第一条记录）时触发全部 segment 的加载与拼接。

**脏数据追踪：** Tasker 对象维护 `loaded_segments`（已读过的 segment 文件名集合）和 `dirty_segments`（被修改过的 segment 文件名集合）。退出时只写回脏段，未修改的段原样保留在磁盘（非脏不写）。扩容边缘（满 500 条）→ 写入时创建新 segment；缩容边缘（段内记录全部删除）→ 写入时跳过该文件。

**段分割策略：** 按数量分段（默认每段 500 条），不按日期范围。新记录追加到最新段，旧段写满后不可变。

**OneDrive 友好：** 分段后单次修改只触发被修改 segment 文件的同步。写入采用原子操作（先写临时文件再 rename），避免同步过程中读到不完整数据。

#### 3.3.2 不采用数据库

SQLite 等嵌入式数据库的二进制文件在 OneDrive 同步时有损坏风险，且不支持手动编辑。JSON 与 OneDrive 的文本对比和手动修正能力完全兼容。

### 3.4 扩展模块系统

#### 3.4.1 设计原则

**记录类型不预定义枚举。** 软件通过字符串标识类型名，启动时各扩展模块向 core 注册自身的处理类，运行时通过类型名字符串 lookup 对应的处理器。

此设计使内置的 default、timer、account 与外来的新记录类型地位相同——都是扩展模块，遵循相同的注册协议。新增"记账"或"标签"类型不影响 core 代码。

#### 3.4.2 注册机制

```python
# 扩展模块在 __init__.py 中注册
from core import ExtensionRegistry
from .task import DefaultTask, TimerTask

ExtensionRegistry.register_task_type("default", DefaultTask)
ExtensionRegistry.register_task_type("timer", TimerTask)
ExtensionRegistry.register_analyzer("attr_count", AttributeCounter)
```

core 包定义 `ExtensionRegistry` 单例和 `BaseTask`、`BaseTasker` 等抽象基类，**不导入任何扩展模块**。扩展模块导入 core 并完成自注册。

#### 3.4.3 模块加载

启动时扫描 `extensions/` 目录，导入所有扩展包的 `__init__.py`（触发注册）。也可通过配置文件指定启用的扩展列表。

## 四、性能与非功能需求

### 4.1 资源占用

- **前台操作**：内存 < 200MB（含 Python 解释器 + Qt 框架 + 数据）
- **后台挂起**：内存 < 50MB（仅托盘图标 + 全局热键监听器，GUI 窗口资源释放）
- **图表模式**：本地 HTTP 服务内存开销 < 10MB（不含浏览器进程——浏览器是用户系统已有资源，不计入软件开销）。浏览器标签页关闭后 HTTP 服务也停止，无持续占用
- **CPU**：空闲时趋近 0%，数据读写为瞬时操作

### 4.2 启动速度

- 冷启动：3 秒内显示主窗口（加载 Qt + 读取 taskers.json）
- 托盘呼出：1 秒内恢复窗口（窗口已隐藏未销毁，仅 show 即可）
- 图表首次打开：额外 1-2 秒（启动 HTTP 服务 + 打开浏览器 + 加载 ECharts CDN）
- 图表再次打开：约 1 秒（浏览器可能已缓存 ECharts JS）

### 4.3 数据规模

- 当前数据约数千条 Task，JSON 文件总大小约数百 KB
- 目标支持：10 万条记录以内，无需索引优化即可流畅操作
- 超过 10 万条时，segment 文件 + 内存索引保证表格视图的滚动和搜索性能

### 4.4 打包

- 使用 PyInstaller 打包为单个 .exe
- 数据目录默认在软件同目录下（便携式），也支持自定义路径
- OneDrive 用户可将数据目录设置在 OneDrive 同步范围内

## 五、使用体验分析

### 5.1 使用场景

| 场景 | 操作流程 | 体验目标 |
|------|----------|----------|
| 快速记录一条待办 | 热键唤出 → 内联输入 → 回车创建 | 全程键盘，< 5 秒 |
| 开始计时（如编程） | 点击"开始编程"快捷按钮 | < 2 秒 |
| 结束计时 | 找到计时器 Tasker → 点"结束" | < 3 秒 |
| 查询账号密码 | 搜索框输入平台名 → 自动复制密码 | < 5 秒 |
| 查看本周时间分布 | 点"图表" → 浏览器打开 → 自动显示 | < 5 秒 |
| 月度 3D 复盘 | 点"3D 可视化" → 浏览器打开 → 翻到对应月 | < 8 秒 |
| 添加新的快捷按钮 | 右键"添加按钮" → 填写预设字段 | < 30 秒 |

### 5.2 交互方式

**三种并行的交互模式，不设立独立的"命令系统"：**

1. **按钮点击**：GUI 按钮（新建、编辑、删除、快捷按钮、打开图表）—— 鼠标操作用户的首选
2. **内联输入**：主界面搜索栏支持的快捷语法（如 `/get 班级` 跳转）—— 键盘操作用户的保留体验
3. **快捷键**：全局热键唤出、`1-9` 触发快捷按钮、`Delete` 删除选中记录、`Ctrl+F` 聚焦搜索

### 5.3 旧项目用户过渡

- 内联输入框支持部分旧命令语法（`/get`、`/sort`、`/info`）
- 数据迁移完成后，旧 pkl 文件保留不删除
- 导出的可读 txt 格式与旧项目 `txt` 指令输出风格一致

## 六、设计目标与原则

### 6.1 架构目标

1. **扩展即一等公民**：内置和外来扩展模块遵循完全相同的注册协议，core 不导入任何扩展
2. **存储分段化**：每个 Tasker 文件夹 + 多 segment 文件，减少 OneDrive 同步开销和冲突范围
3. **图表外部化**：本地 HTTP 服务 + 外部浏览器，资源不嵌入软件，关闭即释放
4. **启动最小化**：只读索引，不预加载数据
5. **双模交互**：GUI 按钮和内联键盘输入同等重要，不偏废任一

### 6.2 技术栈

详见 [技术栈分析](技术栈分析.md)。

核心选型：**Python 3.12+ + PySide6 + ECharts（外部浏览器）**。使用外部浏览器而非内嵌 WebView 使两个候选技术栈在 3D 可视化能力上平等——ECharts GL 均可使用。最终选择 Python 的决定性因素是数据迁移零成本（旧项目 pkl 在同一 Python 环境读取）和扩展模块系统更简洁。

### 6.3 设计原则

1. **同构分形**：所有扩展模块和子管理器遵循相同的接口结构和分层模式——认知一个即认知全部
2. **线性熵增**：GUI 界面膨胀不可避免，但界面与逻辑严格分离使业务层的复杂度保持线性增长
3. **开闭原则**：对扩展开放（注册新类型），对修改关闭（不修改 core 代码）
4. **资源即用即弃**：HTTP 服务、浏览器标签页等资源按需创建，不用即释放
5. **数据安全**：原子写入 + 备份 + OneDrive 冲突友好策略

### 6.4 边界声明

**本项目不涵盖：**
- 多用户协作或权限管理
- 云端同步服务（依赖 OneDrive 等外部同步工具，软件自身不内置同步逻辑）
- 移动端 App
- 自然语言处理或 AI 辅助分类
- 旧模块中的 `school_task`（班级事务专用，需求已随高中毕业而过期）
- `label` 的数据迁移（新架构中 label 作为内置扩展重新实现，而非从旧 pkl 迁移 label 类型数据）

## 七、术语定义

| 术语 | 定义 |
|------|------|
| Tasker | 记录容器，如"班级""计时器""账号"，包含多条 Task 及其扩展功能 |
| Task | 单条记录，核心字段：日期、属性、内容、注释；扩展模块可追加额外字段 |
| 扩展模块 | 实现 `BaseTask`/`BaseTasker` 等抽象基类并注册到 `ExtensionRegistry` 的 Python 包 |
| core | 框架核心包，定义抽象基类、注册表、存储接口——不包含任何具体记录类型的业务逻辑 |
| 快捷按钮 | 用户预设的一键创建 Task 按钮，自动填充预设字段，按使用频率排序 |
| 内联输入 | 主界面搜索栏形式的快速创建入口——支持打字内容 + 回车创建 |
| Segment | Tasker 文件夹内的单个 JSON 文件，按日期范围或记录数分割的 Task 批次 |
| 本地 HTTP 服务 | 图表模式下运行的轻量 HTTP 服务，仅监听 127.0.0.1，为浏览器图表页面提供数据 API |
| 图表模式 | 主窗口的特殊状态——隐藏 Tasker/Task 视图，仅显示图表类型名 + 返回按钮 |
| 外部浏览器 | 用户系统的默认浏览器，用于渲染 ECharts 图表和 ECharts GL 3D 可视化 |
